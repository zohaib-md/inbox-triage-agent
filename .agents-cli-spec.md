# Agent Spec: SaaS Support Inbox Triage Agent

## 1. Problem & Purpose
Automate the triage of an inbound support inbox for a small B2B/B2C SaaS product.
Takes raw email input (subject, sender, body), classifies it into actionable categories, determines confidence, and prepares suggested draft replies for human review.

## 2. Core Capabilities & Policies
- **Input**: Email data object with `subject` (str), `sender` (str), `body` (str).
- **Classification Categories**:
  - `urgent`: Production outages, critical system failures, major security/SLA breaches requiring immediate attention.
  - `needs_reply`: Actionable customer questions (billing questions, reproducible bug reports, feature requests, account inquiries).
  - `fyi`: Automated system notifications, maintenance completion notices, receipts/newsletters where no reply is needed.
  - `spam`: Marketing cold pitches, unsolicited sales outreach, phishing, scam attempts.
  - `needs_human_review`: Ambiguous requests, vague one-liners lacking critical details, or low-confidence classifications (< 0.80).
- **Draft Reply Rules**:
  - Suggested reply draft generated ONLY for `urgent` and `needs_reply`.
  - Replies must be specific to SaaS context (e.g. referencing billing terms, prorations, bug workarounds, escalation status).
  - Strictly NO draft reply for `spam`, `fyi`, or `needs_human_review` (must be `null`).
- **Safety & Human-in-the-Loop**:
  - Agent NEVER sends emails automatically. Output is strictly for human review.
  - Vague emails ("it broke") or low-confidence signals must not be guessed; flag for human review.

## 3. Architecture & Interfaces
- Framework: Google Agent Development Kit (ADK) + Gemini models.
- Output Schema: Pydantic structured output (`TriageResult`).
- Project layout: ADK app structure (`app/agent.py`, `app/schema.py`, `app/tools.py`).
- Evaluation: `tests/eval/datasets/inbox-eval.json` with multi-metric verification in `tests/eval/eval_config.yaml`.
